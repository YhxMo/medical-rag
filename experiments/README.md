# RAG 评测与调参记录

这里整理 RAG 评测与调参材料：参数配置、数据集、逐题中间结果、模型评审、修订、失败案例、运行清单和费用记录。主应用代码在仓库根目录的 `src/`，实验资料独立存放，不参与日常问答。

每组实验保留参数配置、数据集、测量条件和代码快照，原始结果与分析结论可相互核对。指标定义和评测命令见[评测文档](../docs/evaluation.md)。

## 建议阅读顺序

1. [检索策略比较](docs/resume-v2/retrieval_development.json)：baseline、章节增强、BGE 重排的开发集指标和延迟。
2. [多模态实验状态](docs/resume-v2/status.json)：哪些已完成，哪些失败或尚未完成。

自动化测试、真实建库与问答流程的检查结果见[功能验证记录](validation.json)。

## 检索调参结果

开发集包含 10 道标注文本题，单次预热后测量，不计模型初始化：

| 策略 | Recall@5 | NDCG@5 | P95 |
|---|---:|---:|---:|
| 向量 + BM25 + RRF | 0.80 | 0.706 | 0.38 s |
| 加入章节信息 | 0.75 | 0.657 | 0.21 s |
| 章节信息 + BGE 重排 | 0.90 | 0.755 | 1.85 s |

来源：[原始结果](docs/resume-v2/retrieval_development.json)。这支持“在该开发集上，重排提高召回率并增加延迟”的结论。样本量为 10 题，指标衡量相关证据的召回与排序。

其他实验包含 57 题回归集、80 题冻结多模态题集、逐题回答及两轮代理评分。回归集存在已查看问题污染，人工审核数为 0，留出集实验未完成；相关限制和失败记录均保留，不能只展示通过案例。

## 材料布局

```text
config.*.yaml              实验参数配置
CODE_VERSION.txt           实验代码快照
artifacts/resume-v2/        策略选择、构建清单、预算、逐题检索与运行状态
  dev-retrieval/            开发集各策略中间结果
  regression-retrieval/     回归集各策略中间结果
  caption-run/             图像描述与调用记录
data/evaluation/           冻结题集、逐题回答、评分原文、修复与来源复核
docs/evaluation/           分轮报告与指标汇总
docs/resume-v2/            实验方案、开发集结果与状态
docs/archive/             评测题集、参数和指标归档
```

大型 PDF、模型、向量数据库和完整 API 缓存不进入 Git；配置、数据集、中间结果和分析报告随仓库保存。

## 复现实验

按 `CODE_VERSION.txt` 中的提交号准备独立的实验工作目录，以匹配记录中的脚本和配置：

```bash
git worktree add --detach ../medical-rag-experiment-v1 6b386ae
```

然后在该目录按[实验说明](docs/resume-v2/README.md)准备 PDF、模型与配置；在线实验还需要 API 密钥并产生费用。运行清单中的输入哈希可用于核对语料、索引和评分条件。

后续实验应新增目录和配置快照，保留各轮原始结果，再更新对照结论，不覆盖已有记录。

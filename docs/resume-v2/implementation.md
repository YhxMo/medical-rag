# 实现说明与边界

- `src/application/service.py` 是 CLI 和 UI 共用的流程。查询路由、截图解析、英文表达、候选检索、重排序、上下文预算、充分性检查与引用修复都在服务内完成；UI 只处理请求副本、进度及展示。
- 文本证据与模型图片描述使用同一证据模型，描述标记 `derived_by_model`；原图通过登记表和 SHA-256 校验，用户截图作为独立输入，不登记为教材来源。
- `src/application/client.py` 统一文本和视觉请求，文件锁保护跨进程账本，单进程并发上限 2。温度固定 0.1，输出最多 2,048 token。非流式临时错误最多重试两次；流式中途失败不自动重播，避免用户收到重复文字，但未知费用预留仍保留。
- UI 显示流式临时答案后才校验引用。在线实验也读取真实流，分别记录从请求开始到首个答案 token 的耗时及生成接口自身首 token 耗时。缓存回放带 `cache_hit`，不得混入实时延迟统计。
- 冻结选择与回答的缓存输入不含耗时。重新调用已完成的开发选择会核对题集及索引后复用结果，不因重新计时而改写策略。
- 抽样初版只检查图注引用，原页核对发现可能选到无图页；在任何模型调用与出题前改为要求实际大图或图注加矢量路径。初版清单留在本地拒绝记录中，不进入正式准备清单。
- PDF 块仍可能截断词语、公式或条件。此轮保留分块基础以便控制检索变量；原图和证据不足提示只能缓解，不能证明公式识别已经可靠。
- 章节规则缺失时记录 `unknown`。已有 162 个块未识别到可靠章节，不通过模型猜标题。章节增强回归无收益，因此没有强行启用。
- 默认仅监听回环地址；未增加认证、多租户或公网部署，不能称为生产级服务。

## 首次真实视觉接口兼容修复

首次百炼响应将 `units` 返回为字符串列表，而不是提示词约定的单个字符串；第 5 页又将 `visual_relations` 按子图标签返回为对象，两次均在写入索引前被格式校验拦截。归一化现在将纯字符串列表按换行拼接，空列表转换为空字符串；只包含文本的对象或嵌套列表保留键名、层级并序列化为 JSON 文本。缺失字段、null、数字、布尔值及超过 8 层的结构仍拒绝，不自动填补观察结果。原始模型响应留在内容寻址缓存中，修复后复用同一响应，不重新计费；记录 `normalized_text_fields` 便于追踪转换。已用全部 5 份实际缓存响应验证兼容，回归测试覆盖子图标签、嵌套文本、缺失字段和非法值。格式兼容不代表描述语义已经核验。

无回显入口在失败后仅将密钥保留在当前进程内存中最多 600 秒，等待本地 `artifacts/resume-v2/retry.signal` 变化后重试同一命令。该信号不包含密钥或可执行指令。到期、成功退出或 Ctrl+C 后释放密钥；密钥不写入状态文件。此机制用于修复流程错误，不能提高 30 元预算。

第 19 页首次请求失败，账本记录输出正好达到 1,000 token，推断为输出截断；旧客户端未保留该次原始失败正文，因此不能追溯确认结束原因。此次调整保留前 18 页成功缓存，后续页上限提高到 2,048 token，在本地 `caption-run/output_limits.json` 和 `output_limit_revision.json` 记录。新建运行默认采用 2,048；费用预留相应增加，总预算不变。客户端现在保存未完成响应的原始正文、结束原因、用量和输出上限到忽略提交的 `api-cache/failed-responses`，拒绝将其当作成功缓存，并明确报告失败原因。失败费用始终计入账本。

80 题生成期间发现短答案 `99` 被旧的最少 5 字符限制误拒绝，现允许非空短答案，问题与依据仍保留长度校验。直接核对开发组原图发现 Fig. 5.7(b) 的候选答案把投影焦点由阴极侧向阳极侧的长度变化方向写反；在任何系统回答实验之前，按原图修正并保留原始批次、修改依据和图片摘要。修改记录为 `draft_source_review.json`，冻结题集记录修改数量与文件摘要，审核身份明确为 AI 原图检查，不增加人工审核数。

在线报告按任务类型和对照方式分组，保留失败数和来源命中分母；缓存回答不计入实时 P50/P95。上下文字符数、教材原图数量、上传图数量、已知 token 和未知用量数分别报告。回答元数据费用仅覆盖有返回记录的回答调用，最终费用以包含评委、重试及未释放预留的共享账本为准。

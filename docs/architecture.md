# 架构说明

项目包含两个入口流程：离线建库和在线问答。`application/bootstrap.py` 是依赖组装入口，CLI 和 UI 只传递参数、展示结果；业务模块不导入 CLI，也不依赖评测模块。

## 建库

1. `document/loader.py` 使用 PyMuPDF 读取 PDF 文本，保留文件名和从 1 开始的 PDF 页码。
2. `document/chunker.py` 在单页内按字符预算分块，优先在段落、句子或空白处分割，保留重叠文本与字符区间。块 ID 由来源、页码、位置和内容确定。
3. 显式传入 `--captions` 时，`document/ingest.py` 为含位图的页面渲染图片，并生成一次视觉描述，标记为 `image_caption`。
4. `indexer/qdrant_store.py` 把向量写入本地 Qdrant，同时保存 `evidence.jsonl` 和 BM25 索引。

默认每块不超过 900 字符，重叠 100 字符。按页分块让每条证据的引用页码明确，字符重叠保留相邻片段的局部语境；跨页论述可能被切开。

## 问答

1. 英文文字问题直接检索；中文问题可先转换为英文；截图由视觉模型产生检索问题。
2. Qdrant 和 BM25 各召回 20 个候选，使用 `sum(1 / (60 + rank))` 做 RRF 融合，保留 20 个候选。
3. BGE Cross-Encoder 对候选排序，再去重并截取最多 5 块、共 6,000 字符的正文。重排可在配置中关闭。
4. 在线模式用一次模型调用生成带 `[n]` 引用的回答；离线模式直接返回同一批证据。
5. CLI 输出文字或 JSON，UI 展示答案和可展开的来源原文。

通常英文问题调用模型 1 次，中文问题或截图问题调用 2 次。模型不可用时返回错误，由用户决定是否重试。

## 模块边界

| 模块 | 职责 | 不承担的职责 |
|---|---|---|
| `document` | PDF → EvidenceItem | 查询和答案生成 |
| `indexer` | 索引持久化与混合召回 | 模型回答 |
| `reranker` | 候选重排 | 生成与评测 |
| `application` | 依赖组装与查询编排 | 页面组件、实验管理 |
| `ui` / `cli` | 参数输入与结果展示 | 独立检索实现 |
| `evaluation` | 对标注集计算检索指标 | 在线评审或修改答案 |

`EvidenceItem` 是各模块共用的证据格式；文本和视觉描述走同一套存储与检索。视觉描述是模型派生内容，界面明确标注。截图属于用户输入，不被计作教材来源。

## 本地运行约定

- 配置路径相对于 YAML 所在目录，数据与产物位置在配置中明确指定。
- `index` 是完整重建；建库与查询应串行运行，本地 Qdrant 不支持多个进程同时打开同一路径。
- 调整 embedding 模型后必须重建索引，即使新模型的向量维度相同。
- BM25 的 pickle 文件是本机建库产物，不应加载不可信第三方文件。
- `--captions` 会调用配置的视觉服务，每次重建都重新生成描述。

## 评测与实验

评测通过独立命令运行，参数、中间结果和失败案例集中保存在 [experiments/](../experiments/README.md)。运行清单记录输入哈希，配置快照记录检索与重排参数，便于比较不同方案的效果和成本。
